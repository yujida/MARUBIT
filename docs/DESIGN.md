# MARUBIT — 인스타그램 채널 분석 사이트 설계안 (v0.1, 논의용 초안)

> 상태: **초안**. 아래 "결정 필요 사항"을 합의한 뒤 v1.0으로 확정하고 구현에 들어갑니다.

## 1. 목표

- 인스타그램 채널(내 계정 + 경쟁/벤치마크 계정)을 **컴퓨터 유즈(Computer Use)** 로 직접 살펴보고 데이터를 수집한다.
- 수집한 데이터를 **나만의 분석 사이트(대시보드)** 에서 지표·추이·비교로 본다.
- Claude가 데이터를 근거로 **"무엇이 먹히고, 다음에 뭘 올릴지"** 인사이트 리포트를 쓴다.

비목표(v1): 자동 게시, 좋아요/팔로우 자동화(봇), 비공개 계정 열람, 대량 크롤링.

## 2. 왜 컴퓨터 유즈인가 — 데이터 수집 방식 비교

| 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **컴퓨터 유즈** (Claude가 로그인된 브라우저 화면을 보고 읽음) | 로그인 문제 없음(사용자가 이미 로그인한 브라우저 사용), 내 계정의 **인사이트 화면**까지 읽을 수 있음, API 승인 불필요 | 느림(계정당 수 분), 화면에 보이는 숫자만 수집 가능 | **메인 수집기** |
| Instagram Graph API (Claudegram 방식) | 정확한 수치(도달, 저장, 공유, 시청시간) | 비즈니스/크리에이터 계정 + 페이스북 페이지 + Meta 앱·토큰 필요, **내 계정만** 가능 | v2 옵션(내 계정 정밀 분석용) |
| instaloader / instagrapi 등 스크래퍼 | 빠르고 대량 수집 | 인스타 약관 위반 소지, 차단/계정 제재 위험, 로그인 세션 관리 부담 | **사용 안 함** |
| 인스타 "내 정보 다운로드"(JSON) | 공식, 안전 | 내 계정만, 도달/인사이트 수치 거의 없음 | 보조 import 옵션 |

원칙: **사람 속도로, 읽기 전용, 공개 데이터(+내 계정 인사이트)만.** 화면에서 확인 못 한 값은 추정하지 않고 `null`로 남긴다.

## 3. 전체 구조

```
┌───────────────────────── 사용자 PC ─────────────────────────┐
│  브라우저(인스타 로그인 상태)                                  │
│        ▲  화면 읽기/스크롤/클릭                                 │
│  [1] 수집기: Claude 컴퓨터 유즈 + `ig-collect` 스킬             │
│        │  → 스냅샷 JSON (스키마 고정)                           │
│        ▼                                                     │
│  data/channels/<handle>/<YYYY-MM-DD>.json  ──git push──┐      │
└──────────────────────────────────────────────────────│──────┘
                                                       ▼
   [2] 분석 엔진 (TypeScript, 순수 함수)  ← 스냅샷들을 읽어 지표 계산
                                                       ▼
   [3] 분석 사이트 (대시보드)  ← 채널 개요 / 게시물 / 추이 / 비교 / 리포트
                                                       ▲
   [4] 인사이트: Claude `ig-analyze` 스킬 → reports/<handle>/<date>.md
```

### [1] 수집기 — `ig-collect` 스킬 (`.claude/skills/ig-collect/SKILL.md`)
컴퓨터 유즈를 쓰는 Claude(Claude in Chrome 또는 Claude 데스크톱의 computer use)에게 주는 **수집 절차서**.

1. `instagram.com/<handle>` 접속 → 프로필 헤더 읽기(게시물 수, 팔로워, 팔로잉, 이름, 소개, 링크, 하이라이트 수, 인증 여부)
2. 그리드를 스크롤하며 최근 N개(기본 30) 게시물 순회
   - 게시물 열기 → 유형(사진/캐러셀/릴스), 게시일, 캡션, 해시태그, 멘션, 좋아요 수, 댓글 수, (릴스) 조회/재생 수, 캐러셀 장수
   - 상위 댓글 몇 개(선택, 텍스트만)
3. **내 계정이면** 프로페셔널 대시보드/게시물 인사이트에서 도달, 저장, 공유, 프로필 방문 등 추가 수집
4. 스키마에 맞춘 JSON 출력 + 화면에서 확인 못 한 값은 `null`, 스크린샷 근거(선택)
5. 안전장치: 게시물 간 대기, 1회 실행당 계정 수 제한, 좋아요/팔로우/댓글 등 **쓰기 동작 금지**

스냅샷을 날짜별로 쌓아 **팔로워 추이, 게시물별 반응 성장**을 계산한다(Claudegram의 "히스토리를 잊지 않는" 저장 방식 차용).

### [2] 분석 엔진 — 지표 정의
| 구분 | 지표 | 계산 |
|---|---|---|
| 참여 | 참여율(팔로워 기준) | (좋아요+댓글) / 팔로워 |
| | 참여율(도달 기준, 내 계정) | (좋아요+댓글+저장+공유) / 도달 |
| | 릴스 조회율 | 조회수 / 팔로워 |
| | 댓글/좋아요 비 | 대화 유발 정도 |
| 성과 분포 | 상위/하위 게시물, 채널 중앙값 대비 배수 | 평균 대신 **중앙값** 기준(바이럴 1개에 왜곡 방지) |
| 콘텐츠 | 포맷 믹스(사진/캐러셀/릴스)별 성과 | 포맷별 중앙 참여율 |
| | 해시태그 성과 | 태그별 사용 횟수·평균 성과 |
| | 캡션 길이·첫 줄(훅)·CTA 유무 vs 성과 | 상관 경향(인과 아님 표기) |
| | 콘텐츠 카테고리(키워드 규칙 + Claude 분류) | 카테고리별 성과 |
| 운영 | 게시 빈도/주기, 요일×시간 히트맵 | 게시 시각 기준 |
| 성장 | 팔로워 증감, 주간 성장률 | 스냅샷 간 차이 |
| 비교 | 경쟁 계정 벤치마크 | 위 지표를 계정별 나란히 |

### [3] 분석 사이트 — 화면 구성
1. **채널 목록**: 등록 계정 카드(팔로워, 참여율, 최근 수집일)
2. **채널 개요**: KPI 카드, 팔로워 추이, 포맷 믹스, 게시 빈도
3. **게시물 탐색**: 정렬/필터 가능한 테이블 + 썸네일 그리드, 중앙값 대비 배수 하이라이트
4. **콘텐츠 분석**: 요일×시간 히트맵, 해시태그 표, 카테고리별 성과, 캡션 패턴
5. **경쟁 비교**: 2~5개 계정 지표 나란히, 포지셔닝/화이트스페이스 메모
6. **리포트**: Claude가 작성한 인사이트 리포트(Markdown) 열람
7. **가져오기**: 스냅샷 JSON 업로드/붙여넣기(스키마 검증)

### [4] 인사이트 — `ig-analyze` 스킬
GitHub의 MIT 라이선스 마케팅 스킬에서 **프레임워크를 한국어로 재구성**해 사용:
- 성과 리포트: METER (목표 매핑 → 신호 지표 → 정직한 평가 → 3가지 실행 권고)
- 계정 감사: AUDIT (keep / kill / refresh 분류, 프로필 기본기 점검)
- 경쟁 분석: SCOUT (포지셔닝·포맷·주기·화이트스페이스)
- 바이럴 역설계: 상위 게시물의 훅/포맷/주제 메커니즘 추출
- 원칙: **숫자는 수집된 데이터에서만, 없는 값은 지어내지 않는다.**

## 5. 기술 스택 (제안)

- **사이트**: Vite + React + TypeScript + Tailwind, 차트는 Recharts
- **데이터**: v1은 저장소 안의 JSON 파일(`data/`) — 서버/DB 없이 시작, 스냅샷을 git으로 버전관리
- **분석 엔진**: `src/lib/metrics/*.ts` 순수 함수 + Vitest 단위 테스트
- **배포**: 로컬 실행(`npm run dev`) 기본, 원하면 Vercel/GitHub Pages (데이터 공개 여부 주의)
- **v2 후보**: Supabase/SQLite로 저장소 전환, Graph API 수집기, 정기 수집 스케줄

## 7. 결정 필요 사항

1. **분석 대상**: 내 계정 위주? 경쟁/벤치마크 계정 위주? 둘 다?
2. **컴퓨터 유즈 환경**: Claude in Chrome 확장 / Claude 데스크톱 앱 / 기타 중 어떤 걸 쓰실 수 있나요?
3. **내 계정 유형**: 비즈니스/크리에이터 계정인가요? (인사이트 수집 범위가 달라짐)
4. **사이트 공개 범위**: 로컬 전용 vs 웹 배포(비밀번호 보호 필요?)
5. **수집 규모/주기**: 계정 수, 계정당 게시물 수, 주 1회 등
6. **분야(니치)**: 콘텐츠 카테고리 분류 규칙을 맞추기 위해
